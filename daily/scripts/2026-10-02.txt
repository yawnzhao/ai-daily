恭喜你和所有人，又向前踏一步了。

今天是二零二六年十月二日，星期五，AI 日报第二十六期。我们今天围绕一个问题往前走：模型越来越聪明以后，怎样把这些能力变成真正完成的工作？一家银行在扩大使用人工智能，编程工具开始允许用户修改自己，研究者则在问，机器提出更多动作，谁来挑出可靠的那个。最后，我们还会回到两段访谈，听听工具设计和算力成本这两个不同的视角。

先看巴克莱。Anthropic 十月一日宣布，这家银行正在扩大 Claude 的企业部署。公告里的计划是，到今年年底，约一半开发者会采用 Claude Code，明年再覆盖多数软件工程师。注意，这说的是未来采用计划，不能念成一半开发者已经在用了。

更具体的变化在现有流程里。银行的内部知识助手从二零二五年上线，公告称，现在有一万六千多名同事使用，累计搜索超过一百万次。另一套市场业务邮件平台，每天要给大约十二万封邮件分类、补充信息，再转发给合适的人。它不是为了展示能聊几句话，而是在一个每天都会重复的流程里工作。

这些数字来自合作方的公告，我们没有独立审计。公告也强调安全、治理和人工监督。对普通听众来说，我觉得可以先问一个很具体的问题：人工智能替你省掉的步骤，省下来以后交给谁？错误被谁发现，最终由谁负责？一段好看的演示和一个持续运行的流程之间，往往就隔着这些安排。今天这个案例值得看，是因为它让我们知道，大机构把人工智能放在了什么位置。

第二条消息，Claude Code 正式介绍了 mods。你可以把它理解为一小段代码，专门改变这个编程助手的工作方式。它能改写给模型的提示，拦住或者调整一次工具调用，也能改变界面。它跟着插件一起安装和分享，目前支持命令行和桌面应用。

这里有一个很重要的使用边界。官方说，mods 拥有和 Claude Code 相同的本机访问权限，而且没有沙箱。所以安装它，需要像安装其他本机代码一样，信任它的来源。团队和企业可以继续管理插件，受管设备还会先加载默认安全限制，防止用户装的扩展越过已有的拒绝规则。

我的理解是，定制空间变大以后，我们能把工作习惯放进工具里，但同样需要想清楚，什么可以被改，什么必须受控。比如，团队希望每次改完代码都留下测试结果。与其每个人临时想起来再提醒一遍，不如让工具持续呈现这一步。只是，能自动出现一个检查提示，还不等于检查一定可靠，更不等于工具有权替你批准任何动作。

这也把我们带到今天第一段话语场。Thariq Shihipar 在 Anthropic 工作，他在节目里展示了自己尝试的 Claude Code 假设登记工具和模型路由器。Latent Space 是面向 AI 工程师的播客，关注技术、产品和商业实践。

我们选的是九月二十九日访谈里，三十三分钟附近关于 mods 的讨论。Thariq 举了一个例子：一轮工作结束后，可以检查任务是否已经完成，再把问题和答案放到界面上。另一个例子，是给助手一个登记假设的工具，把它在做事过程中依赖的假设留下来，方便最后查看。

这段话吸引我的地方，是它把检查从偶尔记起来的提醒，变成工作过程中的一个环节。如果助手替你做出了选择，你至少还需要知道，它假设了什么、放弃了什么、哪里仍不确定。今天 mods 的公告，让这段较早的讨论多了一个具体入口。但原访谈在公告之前，不是在回应今天的消息；他在节目里提到的探索，也不能都说成默认已经具备的功能。我们核读了官方文字稿相应段落，没有逐字校听录音。

第三条，OpenAI 的 Intelligence Age 平台刊出一篇经济随笔，题目叫《永恒互补》。作者是 Hemanth Asirvatham 和 Elliott Mokski。先把性质说清楚：这是作者的个人观点，不等于 OpenAI 的机构立场，也不是已经发生的经济结论。

文章讨论的是，前沿智力与落地能力可能相互抬高价值。一个更好的科学问题，需要更好的仪器去验证；更好的仪器，又让原来做不到的研究成为可能。作者比较了两种未来，一种更多靠深入推理，在有限扩张下推进；另一种则因为自然界太复杂，越来越需要庞大的实验、组织和后勤来实现想法。

我把它和巴克莱的案例放在一起看，不是说一家银行证明了哪种未来，而是提醒自己：我们习惯问模型聪不聪明，却容易忽略，成果还要经过资料、流程、协作和执行。一个建议再好，如果没有人把它接进工作，没有办法判断是否做对，就还停在建议里。模型能力新闻之后，继续看这些具体安排，能让讨论离生活更近一点。

第四条，NVIDIA 发了一篇谈 AI 工厂回报的文章。它把回报拆成产出能力、硬件使用寿命和实际需求三个因素。机器满负荷能生产多少，只是其中一面；如果产出卖不出去，或者不能持续被使用，漂亮的性能数字也不能直接保证回报。

这篇是厂商文章。我们采用这个分析框架，没有把它的硬件优势、寿命和收益预测当成独立测试结论。对使用者来说，可以从中带走一个朴素的问题：我需要的到底是更多能力，还是更适合手头任务的能力？买来的系统能做很多事情，和我们真的有很多事情需要它做，仍然是两回事。

于是，第二段话语场，我们回听八月二十五日的一次访谈。Dylan Patel 是 SemiAnalysis 创始人兼首席执行官，长期研究半导体供应链、云计算和数据中心成本。Dwarkesh Podcast 是以深入研究为特色的科技类长访谈节目，也讨论其他领域的问题。

这次我们从话语场积累库的一条中文解读，沿原片链接回到英文官方文字稿，选的是十三分钟到二十五分钟附近。Dylan 在里面区分了模型客户最终使用算力，和谁真正拥有那些基础设施。两个口径可以不同，不能因为一种统计把某家公司算进去，就当成它买下了所有设备。

他还讨论，先取得客户承诺，再拿承诺去融资建设，和有自己的资产负债表、可以先建设再寻找用途，处境有什么不同。这不是对今天 NVIDIA 文章的回应，而是一个历史分析视角：谈回报时，除了问机器能产出多少，还要问需求有没有合同支撑，建设由谁融资，收益和风险落在哪一层。

访谈里的未来算力集中、价格与利润数字，属于嘉宾当时的判断和预测。我们今天没有把这些预测念成已经发生的事实。值得现在听，是因为它能帮助我们读懂，当天关于产出、使用寿命和需求的讨论，还缺哪些问题。它提供一个观察角度，不替我们作出投资判断。

再看论文。今天选的是 Mid-Harness，研究终端代理执行下一步之前，能不能多花一点算力，把动作挑好。做法是，让同一个生成器从相同的历史里提出几个候选，再由校验器挑一个交给原来的执行框架。其他候选先不执行。

作者在一个叫 TerminalBench-Lite 的测试里，固定九十亿参数的 TMAX 生成器，用 GPT 五点六 Sol 做校验器，每一步提出八个候选。论文报告的平均成功率，从基线百分之五十提高到百分之六十八点零三。这是论文特定实验的结果，没有在我们的机器上复现。

更值得记住的是，较弱的校验器没有因为候选更多，就得到同样的提升。成对比较在几种受测方式里较好，但会多花调用和输出成本。把强校验器的行为蒸馏回来，也还没把差距消掉。研究还缺少动作正确性的标准标签，没有在同样预算下全面比较，多想一个方案和把一个方案想深一点，到底哪个更划算。

所以，这篇论文不会给我们一个“多开几个代理就会变好”的结论。它提出的问题是，产生选择以后，是否有能力判断选择。这和前面工具里的检查习惯互相呼应，但技术上不是同一件事。也不能把某个测试成功率提高，直接推广成所有任务都更可靠。

最后看开源。Ai2 介绍了 Olmo-core 三，这是面向大型混合专家模型的训练基础设施。混合专家的意思是，模型有很多专家模块，但处理一个小单位的文本时，只激活一部分。听起来能省计算，可完整模型仍然要放进显存，数据还得在设备之间移动，通信和协调也可能吃掉收益。

新系统让专家留在 GPU 上，再把相关数据送过去，减少旧实现反复汇集权重的开销。官方的一项测试，把专家数量从八个增加到一百二十八个，每次仍选四个专家，总参数变大很多，而吞吐下降不到百分之五。这里比较的是指定配置下的系统表现，不能把它当成所有设备的通用结果。

还有一个容易误读的口径。文章里的万亿参数规模，不等于宣布了一个训练完成的万亿模型。一点二万亿参数的测试用了五百一十二张 B300，并采用随机路由来测系统性能；二点三八万亿参数则是短时容量测试。我们看过博文、仓库说明和许可证，没有部署实测。仓库也提醒，驱动、硬件和依赖不同，运行条件就会不同。

今天这些消息连在一起，有一个共同的问题：能力要通过什么过程，变成可验证的结果？银行要安排工作流，工具要留下检查点，算力要找到需求，代理要挑对动作，训练系统则要让各个环节一起工作。把这些过程讲清楚，比只把一个更大的数字念出来，更能帮助我们理解进展。
