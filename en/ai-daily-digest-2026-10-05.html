Security verification

Google pauses some open-source vulnerability submissions as automated reports strain verification

Under Google's official rules, OSS VRP stopped accepting product vulnerability submissions on October 1. Google promises an update in the first quarter of 2027; that does not guarantee submissions will reopen then. The official Google VRP account says automated submissions have increased significantly and the vast majority are invalid. Supply-chain reports and reports already awaiting review are unaffected by this pause. Some Google Cloud issues can still go through other applicable reward programs.

TechCrunch's October 4 report connects the problem to AI-generated reports. The media's attribution to AI should be distinguished from the official account's reference to automated submissions. This should also not be expanded into a claim that Google has shut down all vulnerability rewards. For submitters, a report's value still depends on verifiable impact, steps to reproduce the problem, and evidence that can guide a fix. Faster generation does not automatically produce a matching increase in the recipient's capacity to verify reports.

Business-workflow evaluation

ThinkingBox: an assistant can report completion while the database is still wrong

A joint Microsoft and Hugging Face article published on October 3 introduces ThinkingBox, which uses 507 synthetic business workflows to test whether agents actually get things done. Tasks span five types of scenarios, including retail, travel, insurance, and internal support, with each task repeated 20 times. Evaluation focuses on the final database state, checking both omissions and unintended changes. Some tasks also check requirements for the response.

In one simulated e-commerce example in the article, the assistant makes multiple tool calls but closes a ticket as resolved when it should have remained pending. The process looks smooth, yet the result fails the task. Occasionally finding the right path and succeeding consistently across repeated attempts are different capabilities. These experiments took place in environments controlled by the research team; their results cannot be directly converted into success rates at real companies.

The original paper was first published on August 20. This issue revisits it because of the new joint article. The paper version, the article's model table, and the experimental batches need to be considered separately. In practical work, the assistant's report of completion, tool execution, and the final outcome should likewise be checked separately.

01VISTA lets visual agents look back instead of keeping only text summaries
Visual memory · Public evaluationSubmitted October 1 at 17:59 UTC; added via a media lead on October 4Methods, Table 1, and component experiments; 25 public games; not independently reproduced

This issue revisits the research after a media lead on October 4. The preprint was submitted on October 1 at 17:59 UTC, and an earlier blog post appeared on August 5; it is not presented as a paper newly released today. The MIT team lets models view game images directly, retaining past screens and animation frames as lossless visual memory and enabling active inspection, zooming, and pixel reading.

Across 25 public ARC-AGI-3 games, the authors report a score of 100 for Claude Opus 5.0 with VISTA on action efficiency relative to humans, and 99 for GPT-5.6 Sol. These scores describe game completion and action efficiency under those conditions. They are not scores on the private test set, nor do they establish that AGI has been achieved. Comparisons also involve reasoning settings, action budgets, and execution frameworks, so the entire improvement cannot be attributed to a single component.

In the stepwise experiments with GPT-5.6 Sol, adding lossless visual memory and active inspection raises the score from 70.05 to 94.10; adding pixel reading then brings it to 99. For practical computer tasks, the implication is to preserve evidence that can be revisited, rather than continually expanding text summaries. This issue reviewed the method, Table 1, and the component experiments. No comparable independent full reproduction was obtained; the results are described as the authors' findings.

TesterArmy e2e: natural-language actions checked with locators and assertionsApache-2.0

Discovered through today's GitHub Trending tool review; this does not mean it was first released today. e2e combines natural-language goals, agent actions, and locator assertions in the same test, for web and mobile apps. The README's example asks an assistant to perform an upgrade and then checks the interface state.
