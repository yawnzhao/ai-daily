Anthropic：Claude Sonnet 5.5 作为 5.5 家族第二款模型上线

Anthropic 于 9 月 28 日发布 Claude Sonnet 5.5：相对 Sonnet 5，官方称输出速度提高 30% 以上，多数任务成本最高可降约 30%；每百万输入 token 2 美元、输出 10 美元的单价不变；成本下降指官方测试中完成任务所需 token 减少，不是 API 单价下调。公司将其定位为 Opus 5.5 的更快、更低成本互补：更适合边界清晰的日常任务、修 bug，以及文档、幻灯片与表格制作。

下列评测数字已对照官方发布页表格（未单独完整审阅 System Card）：Terminal-Bench 4.0 为 70.6%（Sonnet 5 为 10.3%）；CursorBench 4.0 为 55.5%。它是首个以截图通关宝可梦红的 Sonnet，也是首个带有与最强模型相近的网络防护与蒸馏防护的 Sonnet。模型已在各平台可用，API 标识为 `claude-sonnet-5-5`。Haiku 5.5 预计数周内加入同一家族。基准分数不等于复杂开放任务上的全面超越；官方仍称 Opus 5.5 在需要持续判断的工作上更强。

来源：Anthropic · 9月28日发布 · 官方发布页表格，未单独完整审阅System Card
安全治理

NVIDIA：推出 Open Agent Safety Platform，把边界放到模型之外

NVIDIA 9 月 28 日宣布 Open Agent Safety Platform：开源运行时 OpenShell 负责 tracing 与策略执行，Sentry 参考设计运行在 BlueField-4 DPU 上，作为带外 watchdog，可在毫秒级隔离越界代理。新闻稿强调，近期多起事件的共同点是代理为完成任务绕过应用层控制。

Anthropic 同步说明与 NVIDIA 的协作：Claude Managed Agents 把代理循环与沙箱分离，凭证放在 vault；再叠 OpenShell / BlueField，企业可限制可达范围并审计行为。新闻稿列出 Anthropic、Microsoft、Hugging Face、Salesforce、SAP、Scale AI、SpaceXAI 等逾百家参与方；OpenShell 以 Apache 2.0 开源。这是厂商公布的平台与合作关系，不等于已在所有生产环境完成独立安全审计。

来源：NVIDIA Newsroom · 9月28日发布 · 含 Anthropic 协作说明 · 已核读 NVIDIA 新闻稿与 Claude Blog
产品

xAI：Team Bots，让整队共用同一套上下文与工具

SpaceXAI（x.ai）9 月 28 日发布 Team Bots：围绕角色或共享工作流配置 Grok Bot，接入文件、插件、凭证与记忆，再分享给团队。官方说明个人对话私密、每人上下文和记忆分别保存，团队共享技能；也可在 Slack 用独立 handle 协作。当前为 Teams 与 Enterprise 计划的公开测试版。

官方举例包括客户成功晨报、工程侧对接 Notion/Linear/Cursor Cloud Agents、营销品牌审稿，以及只读查询数仓的 Data Bot。文中客户与内部使用案例属于发布方陈述，不是本刊实测。它解决的是“同一套能力如何被多人复用”，并不自动保证权限最小化或审计完备。

来源：xAI / SpaceXAI · 9月28日发布 · 已核读官方原文

本刊观察：代理安全正在拆成模型内、运行时与带外三层

把 Sonnet 5.5 的网络/蒸馏防护、Managed Agents 的凭证隔离，与 NVIDIA OpenShell / Sentry 放在一起，可以看到同一方向：模型内对齐不够时，还要把“能做什么”放到模型看不见的边界上。以下是本刊推论，不是上述任一新闻稿已经验证的部署清单。

评估宜分开看：策略能否被证明（OpenShell 提到 policy prover）、越界后能否在毫秒级停止、以及审计日志是否处于代理可篡改范围之外。只宣布合作名单而不公布停机时延与失败模式，读者仍难判断响应是否可靠。

01AgentWorld：多代理协作不能只数消息，也要检查哪些动作真正推动结果
协作评测9月25日提交 · 本期补读全文任务设计、实验设置、表2/3；未复现

这篇预印本原始提交于9月25日17:44 UTC，本轮经9月28日Hugging Face Daily Papers发现，作为旧内容补读，不算9月29日新发表。已核读v1全文的任务设计、实验设置、表2和表3；没有复现。

研究在MMORPG沙箱中设计100个人工标注任务和100个扩增变体，团队包含3至20个能力与角色不对称的代理，任务预算通常为25至55轮。它们不能直接看到队友内部状态，只能通过环境里的消息沟通。13种高层工具把移动、采集和制造等底层操作封装起来，目的是更集中地测量分工和协调。

四个主要被测模型为Gemini 3 Flash、Claude Haiku 4.5、GPT-5 Mini和DeepSeek R1-70B，使用相同提示模板与工具定义。在主任务集，四者成功率依次为52%、45%、36%和20%；扩增集则为24%、26%、21%和10%。这些是论文指定模型和环境下的报告，不是今天所有最新模型的排名。

论文另提出CCE，通过倒推动作之间的因果关系，估计对成功结果有贡献的行动比例。主集最佳模型的平均CCE为0.320，但失败任务按定义记零，所以不能把它直接解释成每次成功任务都浪费了68%的动作。CCE仍借助模型判断因果关系；作者测试了不同裁判，排名稳定，绝对数值有变化。

表3以Gemini 3 Flash对比不同设置：默认多代理成功率52%，关闭沟通22.9%，让一个代理看到所有消息并协调为60%。这说明共享进度有帮助，却没有消除长程规划与资源分配的困难。本刊认为，实际工作流应关心交接是否完成、计划是否能随反馈修订，而不只是代理数量；游戏环境、固定工具和模型版本都限制了这一结论向真实企业任务的外推。
