# 口播稿

一期一个文件，文件名即日期，和 `daily/YYYY/YYYY-MM-DD.md` 一一对应。这里是**念出来的那一版**，音频以它为准。

写稿前必读 [口播写作与证据表达规则](STYLE.md)：用具体例子、短故事和适度幽默帮助理解；以证据归因代替反复播报“未核查、未复现”。本文件保留文件、长度和语音制作约定。

## 它不是成稿的朗读版

`daily/YYYY/*.md` 是成稿，带链接和证据记录。口播稿按听众理解顺序重写：

- 条目数量按当期实际选稿，不固定五条；用自然归因说明证据来自公司、研究作者、媒体或独立评测，不朗读检查日志；
- 结尾回扣当期主题，不固定附逐条核查清单。影响判断的证据缺口在对应条目简短说明，关键材料不足时补查或暂缓，不用免责声明代替证据；
- 数字尽量写成中文读法（「四百一十七票对三票」），避免 TTS 读错；
- `<#1#>` 是停顿标记，单位是秒，不计入正文字数。
- 多音词由 `config/tts-pronunciation.json` 统一注音，使用 `scripts/synth_audio.py` 或在既有请求中传入相同 `pronunciation_dict`。校验、校对、校准、校听的“校”读 jiào（jiao4）；不全局替换“校”，避免影响学校、校园等词。可读口播稿仍保留正常汉字，不能写成“教验/教对”。
- 新增发音修正先用原段短试听确认，接口成功不等于发音已通过听审。已发布节目仅在用户要求时重生成指定范围，试听不自动替换已发布音频。

## 长度

目标 10～13 分钟。moss 音色在语速 1.0 下实测 **5.5～5.8 字/秒**，所以正文 **3,400～4,300 字**；
3,616 字出来是 10:47，3,860 字是 11:47。凭感觉写会严重偏短，2,447 字只有 7:22。

合成参数、接口调用和上传后的回填步骤，见 `audio/README.md`（那个目录不进库）。

mp3 在 `audio/`，被 `.gitignore` 排除。这里只留文字，因为文字是唯一权威、也最该有远端副本的部分。
