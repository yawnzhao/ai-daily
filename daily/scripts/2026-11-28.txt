今天是十一月二十八日，星期六，AI 日报第八十三期。

先做一个更正。昨天第八十二期讲美国的信息公开申请，我们说文章里有受访者担心，限制批量申请的规矩会落到记者、研究人员和移民律师头上。这其实是文章作者自己在结尾给出的判断，原文说的是外州记者、学术研究人员和移民律师。

好，说今天。你跟 DeepSeek 聊完一句，回复下面多了个小图标，长得像一摞硬币。点开一看，是一张小票：这一轮用了多少 token，输入里哪些算缓存命中、哪些没命中，输出又是多少，每样的单价、用量、金额，列得清清楚楚。最底下还有个小圆圈，告诉你这段对话已经占了多少上下文。

这是量子位十一月二十七号报道的，DeepSeek 的网页和 App 上都已经能看到。小票照开，聊天照样免费，DeepSeek 还没公布任何收费方案。token 是什么？按 DeepSeek 价格页的解释，它是模型表示文字的最小单位，可以是一个词、一个数字，也可以是一个标点。

量子位自己测了几笔。开着深度思考，用粤语跟它打个招呼，这一来一回，小票上记的是万分之四元出头。再翻出网页端一轮输入一万三千多个 token 的长对话，算下来也不到一分钱。万分之四元。你没听错，单位是元，前面那个数字是万分之四。

这些价格是从哪来的？量子位对了一下，正好是 DeepSeek 自家 Flash 模型在 API 上的闲时价格。我又去翻了 DeepSeek 的官方价格页，上面写着，工作日白天有几个时段算高峰，高峰时段的价格翻倍。量子位的说法是，以前只有开发者在后台才接触得到的按量计费，现在被原封不动地搬进了普通人的聊天框。

为什么偏偏是现在？报道提了一段背景。十一月十六号，“DeepSeek 使用额度已达上限”上了热搜：免费聊天开始设每日额度，单次能输入的字数被压缩，太久没动过的长对话，也不能再接着聊了。系统提示给的理由很直接，算力不足。

我的看法是，先把小票开出来，比直接甩出一个收费方案要体面。你至少知道自己点了几盘菜，再决定要不要买单。我也有点好奇，等哪天真要付钱了，大家看到小票的第一反应，是觉得便宜，还是开始数自己今天到底追问了多少句。

说到追问，话语场里有一段对话，讲的正是这件事。李丰创办了峰瑞资本，和记者、作家李翔一起主理中文播客《高能量》。这档节目有人物访谈，请创业者还原产品和经营上的决策，也有专门聊产业和宏观经济的栏目。今年十月一号那期宏观漫谈，两人在琢磨，模型进步这么快，应用普及为什么跟不上，还拿搜索和生成式 AI 的成本作了比较，追问云端推理、端侧模型和不同的付费方式，会怎样影响普通用户最后能用上的服务。

按话语场对那一小段原音的转述，李丰说，模型每回答一次，都要先理解问题，再计算，再生成输出。你围着一个问题来回追问，它还得把前面聊过的内容再处理一遍。所以服务的明明是同一个人，对话一长，计算成本也跟着涨。

放到今天那张小票上，说的就是最底下那个小圆圈。圆圈转得越满，你下一句话要背着的上文就越长。所以那位总说“我再问最后一个问题”的同事，在小票上会格外显眼。

算力的账，除了用户这头，还有供给那头。接下来这条，是一条和出口管制有关的消息。据 TechCrunch 转述《华尔街日报》的报道，英伟达已经要求戴尔、超微这些制造合作伙伴，暂停向马来西亚、新加坡、泰国和印度尼西亚四个国家发运服务器。暂停多久没有说，同时要评估当地的合作伙伴，是不是符合美国的出口要求。

为什么是这四个国家？报道说，中国公司此前通过这些国家的数据中心，远程使用英伟达的芯片；美国商务部本月早些时候，把这个口子堵上了。一家美国智库估计，这类远程数据中心，大约提供了中国 AI 算力的百分之二十四。

从芯片怎么卖，说到芯片怎么省电。《连线》十一月二十七号刊出一篇访谈，开头先交代了背景。AI 实验室和云服务商，正跑到斯堪的纳维亚这类可再生能源便宜的地方建数据中心，可物流、关键部件短缺，还有反对数据中心的抗议，一样接一样地拖后腿。于是有一批硬件创业公司换了个方向，想从芯片本身把电省下来。访谈的主角，是其中一家，德国公司 Q.ANT 的创始人兼首席执行官。这家公司做的是光子处理器。普通 GPU 靠电子来搬运和处理数据，光子处理器用的是光波。

他们不打算抢 GPU 的饭碗，想给它当个搭档。创始人的分工说得很干脆：线性运算，请交给 GPU；复杂的非线性计算，交给我们。为什么是非线性？他打了个比方，光是一种波，对应的是正弦函数。只用直线去描述一个圆，你要无数个点；手里有了正弦函数，两个点就能把圆描述出来。他对对手也很客气，说英伟达的 H200 是一件艺术品，在 GPU 的主场很难跟它打。他觉得自己的强项，在图像和视频的识别、分割和生成，还有机器人和物理 AI。在他看来，今天的成本大头是访问内存，完成一件事需要搬的数据少一点，系统就高效一点，而他们能一步算完普通芯片要走很多步的复杂计算。Q.ANT 最近把芯片放进了云服务商 IONOS 的机房做试点，公司说，已经有三十多个工程师团队，在开发专门为光子计算优化的模型。

最大的卖点是省电。创始人说，在模拟里，光子处理器和 CPU、GPU 搭着用，能耗能降低四到五倍。紧接着他自己补了一句：在真实硬件上，还没有演示出来。我有点怀疑这个数字能原样落地，理由就是他补的这一句。模拟器里的赛车，从来不用进站加油。

他还讲了两道挺实在的门槛。一道是软件：现成的 C++ 或 Python 代码可以直接跑，但只为 GPU 优化过的程序，不会自动变快，得做适配。另一道是制造：芯片用两千年代的九十纳米老工艺就能生产，他说要是真来一笔大订单，公司准备好了，担心的是组装环节的供应商跟不跟得上。记者问到那个老难题，开发者等着有硬件才肯写模型，云服务商等着有模型才肯买硬件。他的回答挺有画面感，说公司正在造一只新的鸡，好让大家开始下蛋，蛋好不好吃，一起尝了才知道。至于几年后会不会直接挑战 GPU，他说有机会也不会退缩，但到时候的 AI 工作负载长什么样，他自己也不知道。

省电到底能省多少，今天的论文栏目正好给了一个参照。这是从 Paper-Radar 论文库里挑的一篇关联论文回顾：滑铁卢大学一位硕士生，十月中旬提交到 arXiv 的学位论文。他测的是大模型“量化”以后能省多少电。量化，就是把模型的参数换成更少的位数来存、来算，好比把一张高清原图压成小图。

作者在几种英伟达 GPU 上，比较了一大批量化方案。对照的基线，是没压缩的三十二位全精度模型；而且他刻意没用专门的推理引擎，免得把推理框架的功劳算到量化头上。结果是，八位整数的方案里，带融合内核的那几种省电最稳定，准确率和全精度相比，差距在百分之二点五以内。四位的方案就时好时坏，作者认为，是现在的硬件对四位运算缺少原生加速。

他认为最新的发现，是量化在“长输入、短输出”的任务上最省电。处理提示词的时候，是大块的矩阵乘法，压缩带来的额外开销能摊得开；一个字一个字往外生成的时候，每一步运算都很小，这笔开销就摊不开了。批量开得越大，节能幅度还会再好一点，不过提升有限。还有一个工程结论很朴素：GPU 待机的功耗本来就高，早点把活干完，往往比把功率压低一点更省电。

这两条放在一起听，有个提醒。省多少电，要看任务长什么样、跟谁比、用什么软件来跑。论文里的那些节能倍数，都是跟三十二位的基线比出来的。

换个场景，从机房里的光，说到机房里的视频。Hugging Face 的工程师通过和 AWS 的合作，借到一台 Trainium3 机器，试用一个月，大部分时间都在测试和适配 Hugging Face 上的模型。到了最后五天，作者给自己放了个风，拿 Lightricks 的一个视频模型试着做短片，这个模型能同时生成画面和声音。

输入是一份“电影”文件，像一张分镜表，一个镜头一个名字、一段提示词。镜头之间，可以借前一个镜头的最后几帧，或者后一个镜头的开头几帧来衔接，这样主角从这一镜到下一镜，不会突然换了张脸。作者还借了动画里的老办法：先把整部短片的高潮镜头反复生成，挑出满意的那一条，再让前面的镜头以它的开头几帧收尾，后面的镜头从它的最后几帧接着拍。他的示例短片里，高潮是一座冰山慢慢翻过来，浪头把睡在浮冰上的海豹浇了个透；下一镜，湿漉漉的海豹甩甩头，抖掉水，又趴回浮冰上。真正生成的活，全交给 diffusers 现成的流水线，作者自己写的拼片代码，只是薄薄的一层。

难的是让它在这台机器上跑起来。模型开箱塞不进单个计算核心。第一次跑通的时候，生成一段十秒的短片要五分多钟，而计算核心真正在干活的时间，只占其中一小部分，剩下的时间大多在等。五天之后，在半台机器上、模型加载好以后，一段十秒、带声音的高分辨率短片，二十二三秒就能出来。作者拿 Lightricks 官方接口作对照，官方说生成一段十秒的一零八零P 短片要二十三点七秒。五天下来，追平了官方接口，还略快一点。

我的看法是，这篇文章最值钱的不是最后那个数字，而是中间那个细节：五分多钟里，计算核心大部分时间在等。一块新芯片能不能用起来，常常就卡在这种地方。

这也正是话语场里另一段对话谈过的门槛。季宇以 Mackler 为笔名，写计算机体系结构方面的文章。他本科在清华学物理，后来读了计算机体系结构的博士，在华为工作过，之后创办了行云集成电路，关注 AI 推理的成本和硬件架构。这期《高能量》访谈是二零二四年六月发布的，由李丰主持。按发布方的节目说明，两人回顾了英伟达怎么一步步融进计算机产业，聊了 CUDA 和开发者工具起了什么作用，也聊了新的芯片架构真要部署，得跨过哪些门槛。

两年前的讨论，放到今天再听，就有了两个近例。一个是 Q.ANT 说，为 GPU 优化过的代码不会自动变快；另一个是 Hugging Face 的工程师，花了五天才让视频模型在 Trainium3 上跑快。

接下来回到手机上。The Verge 的资深评测编辑，十一月二十七号写了安卓 AI 自制小组件的上手体验。这个功能叫 Create My Widget，谷歌春天在 I/O 大会上宣布，属于安卓 Gemini Intelligence 那一套功能。目前它还是测试版，本月早些时候才开始推送到 Pixel 手机上。你可以从模板开始，也可以直接描述你想要什么样的小组件。

她先做了个好玩的，每小时换一句《侏罗纪公园》的台词，二十秒左右就做好了。点一下，打开的是 Reddit 上一个电影台词讨论区，她说，背后看不出有什么软件上的魔法，但每次看到台词，确实挺开心。又做了一个下雨时显示提示语的天气小组件。接着她想做点正经的。她每天要散步，想要一个能记一周散步、攒出连续打卡的小组件，最好一眼看过去，就舍不得断。结果拿到的，是一个写着“Log Walk”的按钮，点一下，由 Gemini 把这次散步记进日历。Gemini 倒是另外建议，再加一张按星期打勾的清单。做到这一步，她才发现很多小组件，其实是 Gemini 的提示词快捷方式：点一下，主屏上弹出 Gemini，它思考一会儿，再给你答案。能做的类型，也基本落在几个模板里，比如节日倒计时、球队比分和下一场比赛的时间；更开放的需求，要么去谷歌搜索里找，要么交给 Gemini 现想。

她最想要的，是一个实时的公交到站提醒。赶过车的人都懂，掏出手机，再点进应用，车已经开走了。结果生成出来的，是一块写着“Bus Arrivals”的方块，点开以后，Gemini 给了一段关于班次多久来一趟的文字说明。她要的是一张到站时刻表，拿到的是一篇小作文。她原本期待的，是能按自己喜好定制的迷你应用，实际拿到的，更像一个一刀切的功能。

我的看法是，二十秒做出一个能逗自己笑的小组件，已经挺好玩了；但要说替你干活，它现在更像一个按钮，按下去，还是去问 Gemini。说到主屏，今天开头那张小票，要是哪天也能做成一个小组件，每天早上告诉我昨天跟 AI 聊掉了多少钱，我倒是挺想装一个。

最后一条，从数学说到密码。理论计算机科学家 Scott Aaronson，十一月二十七号在博客上发了一篇文章，写成他和一位财经通讯来电者的对话。对方开口就问：AI 实验室是不是已经破解了 RSA？

他的回答分成两半。前一半，他说自己掌握具体信息，实验室很快会发布一项理论密码分析上的重大突破，但它不会给目前部署的任何密码系统带来迫在眉睫的危险。后一半，至于那些会带来紧迫危险的传闻，他没有具体的、可以据此行动的信息。他还顺手解释，他所说本周早些时候得到证明的 VP 不等于 VNP，是迈向证明 P 不等于 NP 的一步；可 P 不等于 NP，只是基于难题的密码安全的必要条件，还不是充分条件。

我有点担心，这篇文章会被人截成一张图，配上“大牛说密码要完了”。可他白纸黑字写的是，不会马上威胁现有的系统。对话的结尾也很有画面：来电者终于问出真正想问的，读者现在该买哪些加密货币、该抛哪些。他回了一句，走开。

回到今天开头那张小票。万分之四元，你可能连看都懒得看；可它把每一句追问、每一段上文，都老老实实记在了账上。下回再跟 AI 说“最后一个问题”之前，我先点开那摞小硬币，看看圆圈转到哪儿了。

今天的 AI 日报就到这里，我们明天见。
