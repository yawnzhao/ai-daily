# 口播稿

一期一个文件，文件名即日期，和 `daily/YYYY/YYYY-MM-DD.md` 一一对应。这里是**念出来的那一版**，音频以它为准。

写稿前必读 [口播写作与证据表达规则](STYLE.md)。整期结构、故事与幽默、证据表达、更正和编辑自检统一维护在 STYLE；本文件只维护文件、长度、读法和语音制作约定。口播省去来源渠道、字幕/自动转写及是否校对/校订/核读等制作旁白，具体界限与验收统一按 STYLE 第4、7节执行；后台核验和网页引用不省略。

## 文件与制作输入

`daily/YYYY/*.md` 是文字成稿，`daily/scripts/YYYY-MM-DD.txt` 是对应的口播制作输入。两端内容对应与写法按 STYLE 执行；口播改写不覆盖原始标题、型号和来源记录。

`daily/scripts/YYYY-MM-DD.txt` 必须和送进 TTS 的纯口播稿逐字节一致；分段合成时，各段原样拼接也必须和它逐字节一致。音频选定某个 revision 后，这份文件只跟音频走（2026-11-27 用户确认）：之后的文字修正只改正文和网页；音频真的用新 revision 重做了，才换这份文件。已发布音频里的错误按 STYLE 第 5 节在下一期公开更正。纯口播稿只留自然段文字和必要的 `<#n#>` 停顿标记，不能混入【转场……】标记（那只写在带转场的阅读稿里，交接校验会拦）、Markdown 标题或加粗符号、裸链接、未替换的占位符。

## 最小读法表

先确认完整型号和单位含义，再为口播转换；下表示例只说明读法，不是当期新闻数据。不同模型或不同版本不因为同一期出现就合并，阿拉伯数字残留本身不等于错误。

| 类型 | 口播约定 |
|---|---|
| 模型名称、版本 | 保留品牌和型号边界；版本 `5.6` 可写“五点六”。多段版本按原分段读，`2.10` 可写“二点一零”，不省成“二点一”。不能把 `Model-3-8B` 误读为版本“三点八”；先查原型号。不要把正式名里的连字符改成空格：`check_names.py` 能拦 `GPT-4` 这类近似拼写，但实测拦不住 `GPT 4o` 这种拆写，只能自己核对。要用简称，先登记到当期 `official_names` 的 `aliases`。 |
| 参数量 | 确认为参数量后，正文叙述优先用亿：`8B` 为“八十亿参数”，`27B` 为“二百七十亿参数”。模型名中的后缀可先保留，首次顺带说明规模，不把参数量改成版本号。 |
| 内存、存储 | `64 GB` 可读“六十四 GB”，同一期保持一致，首次说明是内存还是存储；不笼统写“六十四 G”。GB、GiB、Gb 及每秒速率不可互换；缩写读不清先短试听，不擅自改单位。 |
| 金额与大数 | 英文 `M`、`B`、`T` 先核准数量级，再换成中文“万、亿、万亿”：`$1.75B` 写“十七点五亿美元”，`$30B` 写“三百亿美元”。必须保留币种，不把美元、欧元简写成“元”或“块”。 |
| 百分比与变化 | `0.5%` 读“百分之零点五”；区分百分比、百分点和倍数。`10x` 在稿里写成“十倍”，不留 `10x`。“达到原来的两倍”与“增加两倍”含义不同，先确认基线再改写。 |
| 年份、日期、期号 | 年份逐位读，如“二零二六年”；月日和期号按通常中文数量读。刊期取北京时间，来源事件日期保留实际时区语境。 |
| 时刻、时长、时间戳 | `07:50` 读“早上七点五十分”，时长 `01:30` 读“一分三十秒”；先区分时刻与时长。节目定位时间戳默认留在网页，必要时口播才读。 |
| 范围、小数、缩写 | `5–10%` 在稿里直接写成“百分之五到百分之十”，不留连字符或波浪号；小数位按实际精度读，不自行舍去有效信息。英文缩写保留大小写和词界，不用错误同音汉字代替。带点号的项目名（如 `llama.cpp`、`Node.js`）保留原样，首次出现时加一句白话定语，如“本地运行模型的开源项目 llama.cpp”。 |

## TTS 与停顿

- `<#1#>` 是一秒停顿标记；沿用现有合成链路支持的 `<#n#>` 写法。字数怎么算见下面「长度」一节。开场结束、话题切换、关键数字前后可按需加停顿；先利用标点和自然断句，不设每板块或每期的数量下限，不连续堆叠来凑时长。试听后调整，不能把标记数量当成语音质量。
- 多音词由 `config/tts-pronunciation.json` 统一注音，词表以这个文件为准，这里不重复列全。例如“校验”“校准”的“校”读 jiao4，“调度”读 diao4 du4，“宏碁”读 hong2 ji1。使用 `scripts/synth_audio.py` 或在既有请求中传入相同 `pronunciation_dict`；不全局替换“校”，避免影响学校、校园等词。可读口播稿仍保留正常汉字，不能写成“教验/教对”。
- 新增发音修正先用原段短试听确认，接口成功不等于发音已通过听审。已发布节目仅在用户要求时重生成指定范围，试听不自动替换已发布音频。

## 长度

纯口播目标 **900～1080 秒（15～18 分钟）**，不含片头、转场音乐和片尾曲（2026-11-26 与中文运行手册统一）。

**估算公式（2026-11-27 起）：时长（秒）≈ 0.207 × 汉字数 + 0.16 × 英文字母数 + 停顿秒数。**

- **怎么数**：汉字是 Unicode 中日韩统一汉字（U+4E00～U+9FFF），英文字母是 A～Z、a～z，标点、空格、换行和阿拉伯数字都不计。停顿秒数是各处 `<#n#>` 的 `n` 之和。Python 写法：`len(re.findall(r'[一-鿿]', text))`。
- **写多少**：英文字母在 150 个左右时，900～1080 秒约是 4,250～5,100 个汉字。写稿瞄准中段，约 990 秒、4,650 个汉字上下，不要贴着下限写。英文多就少写些汉字：100 个英文字母的时长约等于 77 个汉字。
- **为什么不用总字符数**：总字符数把标点、空格和英文字母都按汉字算。英文名多的稿子会因此被高估，第 82 期按 `len(text) × 0.1825` 估了 909 秒，实测只有 856 秒。
- **适用条件**：系数用第 73～82 期的 11 次合成实测拟合，模型 `speech-2.8-hd`、`CN1` 音色、语速 1.0。换模型、音色或语速要重新测。
- **不够时怎么补**（2026-11-26 用户确认）：先补成稿里有、口播还没讲的细节，如条件、对比、人物和动作；成稿本身单薄的，先按 STYLE 第 0 节给成稿补有来源的细节，再进口播；最后才补白话解释。补长度不能突破 STYLE 第 0 节的上限：名词解释每条重点最多一个，"想象""假设""比如"整期合计不超过 8 次。也不靠重复和复述凑数。补完仍不到 900 秒，就在交接的检查记录里如实写估算秒数和原因，不硬凑。
- **以实测为准**：估算只用来控制写稿长度，验收看合成接口或解码出来的实测时长。
- **实测记录**：11 次合成里，新公式的最大误差约 30 秒，多数在 15 秒以内；旧的总字符数算法在英文多的四期（第 73、74、75、82 期）高估了 46～63 秒。

已停用的标准：
- "10～13 分钟、3,400～4,300 字（moss 音色语速 1.0 约 5.5～5.8 字/秒，停顿标记不计）"；
- 2026-11-26 短暂使用的"`len(text)` × 0.1825 秒，约 4,930～5,920 字"。

合成、混音、上传和回填由音频流程在仓库外的私有运行目录完成，规则写在那边的音频工作流说明里；本库没有 `audio/README.md`。直接调用 `scripts/synth_audio.py` 时，要显式传 `--text` 和 `--output`：不传时它会回退到旧机器上的云盘路径。单次请求的文本必须少于 10,000 个字符，超过的要分段。

## 音频本身不在这里

mp3 和合成收据都在仓库外的私有运行目录，不进库。这里是**语音版的唯一文字底本**，也最该有远端副本；事实和数字的权威仍是 `daily/YYYY/*.md` 和当期元数据（见 STYLE 第 0 节）。
