# AI 日报口播写作与证据表达规则

适用于 AI 日报的口播写作；证据表达原则也适用于网页正文。自北京时间 **2026-10-04 刊期**起执行，修订记录见文末。写稿前与本目录 [README.md](README.md) 一起读取。本规则取代旧版“逐条播报未核查、未复现”和固定结尾核查清单的要求，不追溯重做已发布稿件或音频；发现事实错误仍须按本文件的更正规则处理。

**执行层级：**事实准确、来源归属、不得编造、重要限制、必要更正及网页与口播的一致性属于必须遵守的要求。开场形式、板块顺序、例子与幽默的选用、人称偏好属于写作建议，按内容取舍；不设段子、故事或停顿的数量配额。朗读、发音和长度约定以 README.md 为准。

## 1. 节目定位

做一份准确、听得懂、有画面感的日报。帮助听众理解发生了什么、为什么值得关注，以及与自己的工作和生活有什么关系。表达可以轻松、有趣，事实与归因要清楚。

日报的职责是阅读来源、比对关键事实、寻找相关证据和解释意义；默认不承担亲自做性能测试、部署产品或复现实验的任务，也不要求听众替日报完成这些工作。没有自行复现不是每条新闻都要播报的缺陷。编辑仍须核对出处、日期、数字、原话与上下文，不能把这项基本工作省掉。

## 2. 先让听众听懂

- 用短句和具体动词。一个句子尽量只推进一个意思；长英文名、多个缩写和参数不要连续堆叠。
- 术语第一次出现时，用一句白话说明它解决什么问题，再决定是否需要读英文名或缩写。
- 关键数字说清比较对象、时间范围和单位。非必要参数留在网页，不用朗读完整实验表。
- 优先用熟悉场景解释抽象概念：查资料、写作、做日报、会议、整理文件、学习或协作。场景须贴合概念，不能每期都套同一个日报例子。
- 一个例子解释一个概念，通常一两句话。先讲问题，再讲技术怎么起作用，必要时交代类比止于哪里。事实已经清楚的新闻不用硬加例子。
- 让条目顺着“发生了什么 → 为什么重要 → 一个具体解释或场景 → 接下来值得看什么”展开，按题材取舍，不机械朗读四个小标题。

### 整期骨架与叙述人称

- 开场须交代节目名、当期北京时间日期、期号和一句主线。可先用问题、短故事或已有开场语吸引注意，再补齐信息；不用每期重复同一句欢迎词。
- 中段按主线串联当期实际采用的新闻、研究、工具和话语场。口播可调整顺序、合并重复信息、压缩部分简讯，不要求六个固定板块或逐条朗读网页；网页现有四栏目保持不变。话语场仍讲述与网页相同的一组精选，保留嘉宾一句、节目一句及与当期新闻的关联。
- 收束回到本期最值得记住的问题或后续看点，简短告别。仅在本期确实接续歌曲时自然引入，歌名与主题须和实际成品一致；制作状态未确认时先留内部待办，不把承诺或占位符念进成品。歌曲是否制作仍按现有音乐流程执行。
- 编辑叙述默认用“我们”，减少书面化的“本刊”和无信息的“我觉得”。能直接说明判断和依据时，就不加人称；人物引语中的“我”保持归属，不统一替换。人称混用是润色提醒，不单独作为判错依据。

## 3. 故事、段子与严肃内容怎样结合

优先采用三种写法：

1. **有出处的小故事**：从原报道或原节目中的人物、任务、困难和结果切入。只讲材料支持的动作与细节，不补写人物心理、对话、现场见闻或因果关系。
2. **明确标注的假设场景**：用“比如”“想象一下”开头，让听众看到技术在熟悉任务中意味着什么。不可包装成记者亲历、真实客户案例或论文实验。
3. **轻巧的反差与回扣**：借日常工作中的反差点出关键问题；后面的新闻或话语场可以回扣前面的例子，让整期有连贯感。笑点服务解释，讲完要回到事实。

幽默可以来自大家熟悉的工作烦恼、对字面意思的误会或夸张的比喻；不靠编造性能、虚构人物原话、制造冲突或贬损群体。明显属于修辞的夸张不能带出假的事实判断。伤亡、灾难、受害经历等内容不作笑料，严肃议题按内容选择语气。

不设每条或每期必须几个段子的配额。不强行玩梗、不为了押韵删关键条件，不用“颠覆、封神、吊打一切”等词替代解释。若笑话需要长篇铺垫，或删掉后信息更清楚，就删掉。

## 4. 把“我们没做什么”改成“现有证据说明什么”

### 自然归因，不逐条自我免责声明

不再固定播报“本刊没有核查”“我们未独立实测”“没有复现”“没有逐字校听整集”。也不在结尾机械汇总哪些读过、哪些没读过。

根据实际证据，优先说：

- 官方发布或公司自测：“公司公布……”“按照公司这组测试……”
- 作者实验：“研究团队在这组样本中发现……”
- 独立评测：“另一家评测团队在……条件下测得……”
- 仅读摘要但足以支持简短推荐：“论文摘要报告……”
- 节目观点：“他在这段访谈里认为……”
- 编辑解释：“可以把它理解成……”“放到日常工作里，这意味着……”

归因通常在该条首次出现时交代一次。后续关键数字若换了来源，或容易被误解，再补一句。表达归因不用反复加“这是本刊分析，并非作者原话”，但编辑推断不能伪装成他人的结论或回应。

### 只保留会改变理解的条件

不删关键边界：公告日不等于上市日；小样本不代表所有人；特定模型/硬件/任务的加速不代表普遍加速；只测生成阶段不代表完整流程；预印本不等于已经同行评审。用一句具体条件代替笼统的“未经验证”。

如果原始材料无法打开、证据相互冲突或关键数字无法支持，应补查、缩小表述或暂缓采用。仅剩可靠媒体转述且符合快讯准入时，明确归因给该媒体；不能为了口播流畅把尚未证实的说法讲成事实。

### 定向寻找别人的评测、复核与复现

对重点中的性能提升、研究突破、效果或可靠性争议，先看已有候选和材料；若相关结论影响选稿或听众判断，再按项目名/论文名/版本定向查独立测试、复现报告、公开评审或争议回应。普通发布日期、功能公告等不强求每条都找到复现实验，也不为等待证据拖住整期。

先做一轮定向查找，例如围绕名称、版本及待验证主张进行两三个查询；这是起步建议，不是查询配额或核验完成标准。有可用线索再追原始材料，无有效线索就停止扩散。开始时依据当期制作安排确定补查截止时间，给写稿、合成和发布检查留出时间；在既有编辑记录中记实际检索词、范围、截止时间与处理决定。到截止时仍不清楚的核心事实须缩小表述或暂缓采用，不能用超时替代证据，也不能把第三方结果暂缺写成原主张已被否定。

- 回到第三方自己的报告、论文、测试方法或代码说明，核对作者身份、利益关系、日期、模型/软件版本、任务、指标和结论范围。
- 区分独立复现、局部实测、作者自行复测、媒体体验、评论和复述。代码开源、同行评审、多家媒体转载或一句“我也试了”，都不能自动写成“已独立复现”。
- 条件相同或可比时才谈支持/反驳；部分支持就说清哪一部分，条件不同时不制造真假对决。有冲突可讲最影响判断的分歧，不强行下定论。
- 实际检索后未找到可靠第三方结果，内部记检索范围和截止时间。口播通常用“这是作者在……条件下的结果”即可；只有独立证据缺失本身影响判断时，才说“截至本期，在已查到的公开材料中，还没有看到可对照的独立结果”。不能泛称“没有人复现”。
- 不为填这一项制造新的采集来源、全量重跑或亲自复现实验。

## 5. 证据记录留在哪里

证据仍保存到当期既有收据的 `editorial_review`，与条目 ID 对应，不另建一套台账。沿用已有字段；第三方证据需要时附 `supporting_evidence`，记录报告原链接、作者/机构、日期、证据类型、版本与条件、支持或质疑的具体主张、实际阅读位置、利益关系（未知就记未知）。检索无结果只记真实范围，不生成空洞的已验证标签。

`verification_scope` 继续如实记录编辑实际读到的范围；内部的未读、未实测和未复现状态不能为了好听改成已完成。网页公开来源行优先交代“官方公告/作者实验/独立评测/媒体体验”等证据性质；详细检查范围可以留在折叠说明与收据，影响结论的限制仍放在正文。技术收据和私人素材不进入口播。

### 网页信息与口播信息分开处理

- 原节目的精确日期、可定位的时间戳和实际阅读范围保留在网页与收据；口播通常说“在这段访谈里”，不用念一长串起止分秒。必要的时间背景不能省：用“去年一次访谈中”或具体日期避免听众误以为嘉宾正在回应今天的事件，不必把每段都讲成日期核查报告。
- “采集不完整”是否触发，仍按 AGENTS.md 和收据判断，网页及运行报告照实呈现。口播仅在覆盖缺口明显影响本期选题或判断时简短说明具体影响；不因 `partial` 状态自动加固定结尾，也不能在口播宣称全覆盖。没有抓到不等于没有更新。

### 草稿修改与已发布更正

- 本期未发布草稿中的错误，直接修正并同步相关文字、数字和音频制作输入，不播“这里原稿需要修正”等编辑过程。
- 已公开的重要事实错误，在下一份新制作口播的开场之后、主体之前，用一两句话指出被更正的刊期、原说法及正确说法；不反复朗读错误，不用模糊的“稍有偏差”代替更正。
- 公开文字记录按 AGENTS.md 的历史更正规则处理：在当期正文加更正并指向原刊期，不自行覆盖历史稿件或重发历史音频。涉及历史页面回填或重发的额外操作仍遵守原有授权范围。内部草稿修改不冒充公开更正。

## 6. 示例：信息不变，表达更生动

以下是写法示范，不是新的采集证据，也不要机械复制成每天的固定段子。

**完整任务评估：用听众熟悉的例子。**

> 比如做一份 AI 日报，稿子写得再漂亮，链接打不开、音频漏了半段，也还不能算交付。模型交了作文，我们要交的是一份能听、能看的日报。所以要比较的，是整件事做成需要多久、花多少钱。

这是说明性的假设场景，不表示今天真的发生过故障。

**工具调用评测：一句轻巧的反差。**

> 想象让助手订一张票，它回答“正在订票”，评测就给了满分。嘴上已经出发，车票还没到手。这个例子说明的是：提到一个动作，和真的完成动作，要分开评分。

假设场景不等于论文原实验；下一句应回到论文实际测试的任务与范围。

**证据表达：保留具体条件，省去自我免责声明。**

旧写法：“厂商给出了加速数字，我们没有实测，也没有独立复现。”

可改为：“按照厂商的测试，在【模型与硬件条件】下，【明确指标】达到基线的【经核对倍数】。换一种任务，结果可能不同。”

方括号仅用于说明写法，成稿须用当期来源支持的事实替换；材料不足时删除相应主张，不得朗读占位符。若已有可比的第三方评测，应改讲第三方是谁、测了什么、结果是否一致，不继续套用“我们没测”的句子。

**科研快讯：讲证据本身。**

旧写法：“我们读了方法和局限，没有复现，不能推广到所有模型。”

可改为：“这组实验观察到【具体结果】，但比较范围只有【原文实际覆盖的对象与条件】。它提示了【有依据的意义】，还不足以推广到【原文未覆盖的范围】。”

这同样是结构示意，不能把示例中的主张或条件当作下一期已经核到的事实。

## 7. 写稿与验收顺序

1. 确定本期新闻、话语场和论文选题，先整理来源与关键主张；按重要性定向补查相关第三方证据。现有来源准入和事实准确要求继续适用。
2. 按听众理解顺序写口播；从适合的条目选用场景、短故事或轻巧反差。不为凑故事改动事实，不为凑篇数或段子拉长节目。
3. 从听众角度通读：一个不了解术语的人能否听懂？故事是真实有出处还是明确假设？轻松表达是否帮助记住事实？删去重复归因、工作日志、固定免责声明和重复背景。
4. 按下表核对正文、网页与口播。口播可以压缩解释和换顺序，不能新增没有证据的事实，也不能把候选库数量说成实际采用量。
5. 按 README.md 的长度、发音字典和 TTS 规则制作；时长目标靠删重复、提高清晰度实现，不靠删掉关键条件或提升语速。发音改动按既有短试听流程验收。

### 成稿自检清单

| 检查项 | 验收方式 |
|---|---|
| 日期、期号、名称与数字 | 日期和期号与本期元数据一致；人物身份、模型完整名称、版本、参数量、单位、比较基线和百分比与来源对应。数值改写成中文读法不能改变含义。 |
| 选题与条数 | 重点上限从当次配置读取；区分重点、短讯、论文与候选计数。口播所说“几条”与实际讲述一致，不强求网页与口播总条数相等。 |
| 话语场 | 两端采用同组精选，按现有规则验收一至三条、人物与节目背景、新闻关联及原语境；无合格内容时如实报告缺项，不能为了数量编造。 |
| 证据与更正 | 关键归因、限定条件和引语归属一致；检查是否有须公开更正的旧错误。本期草稿的修订过程不进入口播。 |
| 采集状态 | 网页与运行记录的覆盖标记一致；口播不得与之矛盾，是否播缺口按第 5 节判断，不要求复述收据。 |
| 故事与成品 | 假设与真实故事能分清，笑点没有带入假事实；无未替换占位符、内部待办、草稿批注或未经确认的歌曲引入。 |

成稿前搜索下列提醒词及相近表述，逐项看上下文后删除、改写或有理由保留：

“没有核查”“未核查”“没有实测”“未独立验证”“没有复现”“没有部署”“没有逐字校听”“我们读了指定段落”“这里原稿需要修正”“这是本刊的关联分析”“并不是嘉宾逐字给出的清单”。

这是人工自检提示，不是禁词表，不得全局替换；人物引语、必要的证据限制和公开更正可能合理命中。归因通常说一次，换来源或有歧义时仍须补充，不以“每条最多一次”删掉必要信息。此类风格提醒不新增禁词检查脚本；正式名称按 AGENTS.md 获准的原文名称门槛另行核对；字数、阿拉伯数字、人称和停顿标记只作辅助判断，试听与事实核对不能被计数代替。

## 8. 常用术语的编辑约定

先维护高频词，不为凑数量扩表。表内白话说明只是介绍角度，实际含义仍以当期材料为准；原文讨论更细的概念时保留区别。固定读法与语音标记见 README.md。

| 原词 | 优先写法与解释角度 |
|---|---|
| agent | 智能体；首次可结合本条任务解释它如何调用工具、执行步骤。 |
| tool calling | 工具调用；区分提出调用、实际执行和任务完成。 |
| inference | 模型推理；按上下文讲“运行模型产生结果”，不自动等同于 reasoning 能力。 |
| reasoning | 推理能力或推理过程；和 inference 的运行阶段含义分清。 |
| post-training | 后训练；依来源解释具体做法，不统一改成“重新训练”。 |
| fine-tuning | 微调；不要把所有后训练或提示词调整都叫微调。 |
| context window | 上下文窗口；可解释为一次任务中模型能够处理的信息范围，不等同于长期记忆。 |
| benchmark | 基准测试；同时说明测什么，不把一种测试当成总体能力。 |
| preprint | 预印本；按论文实际状态交代，不因进入平台就说已通过同行评审。 |
| open weights | 开放权重；许可证与可商用条件另查，不直接改写成完全开源。 |

硬件词如 unified memory、shared memory 须按原文所指架构和正式名称翻译，不能只为跨期统一而相互替换。新增术语先查清上下文与可靠出处，再补最短必要说明。
