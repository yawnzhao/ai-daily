# AI 日报口播写作与证据表达规则

2026-10-03 经用户确认，自下一份新制作的口播稿起执行。适用于 AI 日报的口播写作；证据表达原则也适用于网页正文。写稿前与本目录 README.md 一起读取。本规则取代旧版“逐条播报未核查、未复现”和固定结尾核查清单的要求，不修改已发布稿件或音频。

## 1. 节目定位

做一份准确、听得懂、有画面感的日报。帮助听众理解发生了什么、为什么值得关注，以及与自己的工作和生活有什么关系。表达可以轻松、有趣，事实与归因要清楚。

日报的职责是阅读来源、比对关键事实、寻找相关证据和解释意义；默认不承担亲自做性能测试、部署产品或复现实验的任务，也不要求听众替日报完成这些工作。没有自行复现不是每条新闻都要播报的缺陷。编辑仍须核对出处、日期、数字、原话与上下文，不能把这项基本工作省掉。

## 2. 先让听众听懂

- 用短句和具体动词。一个句子尽量只推进一个意思；长英文名、多个缩写和参数不要连续堆叠。
- 术语第一次出现时，用一句白话说明它解决什么问题，再决定是否需要读英文名或缩写。
- 关键数字说清比较对象、时间范围和单位。非必要参数留在网页，不用朗读完整实验表。
- 优先用熟悉场景解释抽象概念：查资料、写作、做日报、会议、整理文件、学习或协作。场景须贴合概念，不能每期都套同一个日报例子。
- 一个例子解释一个概念，通常一两句话。先讲问题，再讲技术怎么起作用，必要时交代类比止于哪里。事实已经清楚的新闻不用硬加例子。
- 让条目顺着“发生了什么 → 为什么重要 → 一个具体解释或场景 → 接下来值得看什么”展开，按题材取舍，不机械朗读四个小标题。

## 3. 故事、段子与严肃内容怎样结合

优先采用三种写法：

1. **有出处的小故事**：从原报道或原节目中的人物、任务、困难和结果切入。只讲材料支持的动作与细节，不补写人物心理、对话、现场见闻或因果关系。
2. **明确标注的假设场景**：用“比如”“想象一下”开头，让听众看到技术在熟悉任务中意味着什么。不可包装成记者亲历、真实客户案例或论文实验。
3. **轻巧的反差与回扣**：借日常工作中的反差点出关键问题；后面的新闻或话语场可以回扣前面的例子，让整期有连贯感。笑点服务解释，讲完要回到事实。

幽默可以来自大家熟悉的工作烦恼、对字面意思的误会或夸张的比喻；不靠编造性能、虚构人物原话、制造冲突或贬损群体。明显属于修辞的夸张不能带出假的事实判断。伤亡、灾难、受害经历等内容不作笑料，严肃议题按内容选择语气。

不设每条或每期必须几个段子的配额。不强行玩梗、不为了押韵删关键条件，不用“颠覆、封神、吊打一切”等词替代解释。若笑话需要长篇铺垫，或删掉后信息更清楚，就删掉。

## 4. 把“我们没做什么”改成“现有证据说明什么”

### 自然归因，不逐条自我免责声明

不再固定播报“本刊没有核查”“我们未独立实测”“没有复现”“没有逐字校听整集”。也不在结尾机械汇总哪些读过、哪些没读过。

根据实际证据，优先说：

- 官方发布或公司自测：“公司公布……”“按照公司这组测试……”
- 作者实验：“研究团队在这组样本中发现……”
- 独立评测：“另一家评测团队在……条件下测得……”
- 仅读摘要但足以支持简短推荐：“论文摘要报告……”
- 节目观点：“他在这段访谈里认为……”
- 编辑解释：“可以把它理解成……”“放到日常工作里，这意味着……”

归因通常在该条首次出现时交代一次。后续关键数字若换了来源，或容易被误解，再补一句。表达归因不用反复加“这是本刊分析，并非作者原话”，但编辑推断不能伪装成他人的结论或回应。

### 只保留会改变理解的条件

不删关键边界：公告日不等于上市日；小样本不代表所有人；特定模型/硬件/任务的加速不代表普遍加速；只测生成阶段不代表完整流程；预印本不等于已经同行评审。用一句具体条件代替笼统的“未经验证”。

如果原始材料无法打开、证据相互冲突或关键数字无法支持，应补查、缩小表述或暂缓采用。仅剩可靠媒体转述且符合快讯准入时，明确归因给该媒体；不能为了口播流畅把尚未证实的说法讲成事实。

### 定向寻找别人的评测、复核与复现

对重点中的性能提升、研究突破、效果或可靠性争议，先看已有候选和材料；若相关结论影响选稿或听众判断，再按项目名/论文名/版本定向查独立测试、复现报告、公开评审或争议回应。普通发布日期、功能公告等不强求每条都找到复现实验，也不为等待证据拖住整期。

- 回到第三方自己的报告、论文、测试方法或代码说明，核对作者身份、利益关系、日期、模型/软件版本、任务、指标和结论范围。
- 区分独立复现、局部实测、作者自行复测、媒体体验、评论和复述。代码开源、同行评审、多家媒体转载或一句“我也试了”，都不能自动写成“已独立复现”。
- 条件相同或可比时才谈支持/反驳；部分支持就说清哪一部分，条件不同时不制造真假对决。有冲突可讲最影响判断的分歧，不强行下定论。
- 实际检索后未找到可靠第三方结果，内部记检索范围和截止时间。口播通常用“这是作者在……条件下的结果”即可；只有独立证据缺失本身影响判断时，才说“截至本期，在已查到的公开材料中，还没有看到可对照的独立结果”。不能泛称“没有人复现”。
- 不为填这一项制造新的采集来源、全量重跑或亲自复现实验。

## 5. 证据记录留在哪里

证据仍保存到当期既有收据的 `editorial_review`，与条目 ID 对应，不另建一套台账。沿用已有字段；第三方证据需要时附 `supporting_evidence`，记录报告原链接、作者/机构、日期、证据类型、版本与条件、支持或质疑的具体主张、实际阅读位置、利益关系（未知就记未知）。检索无结果只记真实范围，不生成空洞的已验证标签。

`verification_scope` 继续如实记录编辑实际读到的范围；内部的未读、未实测和未复现状态不能为了好听改成已完成。网页公开来源行优先交代“官方公告/作者实验/独立评测/媒体体验”等证据性质；详细检查范围可以留在折叠说明与收据，影响结论的限制仍放在正文。技术收据和私人素材不进入口播。

## 6. 示例：信息不变，表达更生动

以下是写法示范，不是新的采集证据，也不要机械复制成每天的固定段子。

**完整任务评估：用听众熟悉的例子。**

> 比如做一份 AI 日报，稿子写得再漂亮，链接打不开、音频漏了半段，也还不能算交付。模型交了作文，我们要交的是一份能听、能看的日报。所以要比较的，是整件事做成需要多久、花多少钱。

这是说明性的假设场景，不表示今天真的发生过故障。

**工具调用评测：一句轻巧的反差。**

> 想象让助手订一张票，它回答“正在订票”，评测就给了满分。嘴上已经出发，车票还没到手。这个例子说明的是：提到一个动作，和真的完成动作，要分开评分。

假设场景不等于论文原实验；下一句应回到论文实际测试的任务与范围。

**证据表达：保留具体条件，省去自我免责声明。**

旧写法：“厂商给出最高一点七倍，我们没有实测，也没有独立复现。”

可改为：“在厂商指定的模型测试中，两台机器组合后，性能最高达到原来的约一点七倍。换一种任务，结果可能不同。”

这里的数字与条件来自本刊既有条目；后续使用时必须以该期实际来源为准，不能沿用成通用参数。若已有可比的第三方评测，应改讲第三方是谁、测了什么、结果是否一致，不继续套用“我们没测”的句子。

**科研快讯：讲证据本身。**

旧写法：“我们读了方法和局限，没有复现，不能推广到所有模型。”

可改为：“这组实验只比较了两个训练经历不同的小模型，其中部分训练还没完成。它提醒我们评分可能漏看真实动作，但还不足以说明所有工具评测都有同样的问题。”

## 7. 写稿与验收顺序

1. 确定本期新闻、话语场和论文选题，先整理来源与关键主张；按重要性定向补查相关第三方证据。现有来源准入和事实准确要求继续适用。
2. 按听众理解顺序写口播；从适合的条目选用场景、短故事或轻巧反差。不为凑故事改动事实，不为凑篇数或段子拉长节目。
3. 从听众角度通读：一个不了解术语的人能否听懂？故事是真实有出处还是明确假设？轻松表达是否帮助记住事实？删去重复归因、工作日志、固定免责声明和重复背景。
4. 对照正文检查关键数字、条件、引语归属和事实是否一致。口播可以压缩解释和换顺序，不能新增没有证据的事实。话语场保留嘉宾一句、节目一句及与新闻的关联。
5. 按 README.md 的长度、发音字典和 TTS 规则制作；时长目标靠删重复、提高清晰度实现，不靠删掉关键条件或提升语速。发音改动按既有短试听流程验收。

下一期开始试行，结合后续几期反馈与既定周回顾，观察听懂程度、重复免责声明是否减少、幽默是否自然和信息是否准确；不额外新建定时任务。
