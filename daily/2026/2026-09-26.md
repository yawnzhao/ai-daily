# AI 日报 · 2026 年 9 月 26 日

Claude 开放插件提交流程，Codex 走进售前演示，UNESCO 更新教师 AI 课程。

今天关注 AI 怎样进入具体工作：开发者如何把工具交到用户手中，业务人员如何把需求变成可以讨论的演示，教师又如何带学生理解 AI 带来的变化。

## 每日精选

<!-- item:claude-plugins -->
### Claude 开放插件提交流程，从写好工具走向审核与分发

Claude 9 月 25 日公布新的开发者提交入口。付费套餐用户可以提交远程 MCP 连接器，也可以提交托管在 GitHub 上的插件包，把连接器和 Agent Skills 等能力一起交付。

提交后，系统会进行自动校验与安全扫描，开发者可以跟踪审核进度、处理反馈。**通过审核之后，还需要开发者选择发布**；提交成功不代表插件已经对外上架。发布后，后台会提供安装量等使用数据，帮助开发者了解工具是否被采用。

值得分清的是开放节奏：提交入口已经推出，Claude 与 Claude Code 之间更统一的发现体验仍将在未来几周逐步上线。现有已上架的连接器、技能和插件，无须因为这次调整立即改造。

**为什么值得看**：对于做垂直工具的小团队，开发工作开始延伸到上架、审核反馈和版本维护。能调用一个工具只是起点，用户能否找到它、理解它的用途并持续使用，才决定这项能力能否进入日常工作。

<!-- item:codex-proaction -->
### Codex 帮业务人员制作客户演示，先把需求讲清楚

OpenAI 发布车队管理软件公司 Proaction 的使用案例：不以编程为主要工作的联合创始人，把客户通话记录、邮件和表格交给 Codex，制作贴近客户实际车队的 HTML 演示。

这种演示的作用，是让客户看见拟议中的流程，并让工程师在接手时获得更具体的需求。它位于产品开发之前，不能直接等同于可上线的业务系统。

公司自报每月制作约 **4～6 个演示，每个耗时 30～45 分钟**。这些数字来自厂商刊载的客户案例，本期没有独立测量。文章标题中的增长幅度，也不宜直接解读为营收增长：正文讨论的是销售机会从首次接触推进到方案开发的比例，以及团队对节省工时的估算。

**可借鉴之处**：先用可讨论的界面，把客户口中的“需要一个功能”拆成具体操作与反馈。之后再由工程团队核实数据、权限、异常处理和真实系统对接，减少需求靠口头往返解释的成本。

<!-- item:unesco-course -->
### UNESCO 教师 AI 课程开放第三期，新增葡萄牙语

UNESCO 9 月 25 日宣布，数字公民与人工智能免费在线课程第三期将于 **10 月 12 日**开始。课程面向教师、教育团队及相关社会工作者，在英语、西班牙语之外，新增葡萄牙语版本。

课程包含五个模块，围绕数字足迹、错误信息、信息过滤、AI 伦理及参与公共生活等议题展开，结合视频、案例与讨论。重点是帮助教育者把技术放回学生的日常数字生活，而不只是教授工具操作。

**参与条件**：按公告，完成至少 80% 的课程内容及考核要求，方可取得证书。9 月 25 日是公告日期，10 月 12 日才是本期课程开始日期；报名信息以原文链接中的课程入口为准。

**为什么值得看**：学校讨论 AI 时，容易把注意力集中在作业能否使用、答案是否准确。这门课程提供了另一组教学入口：信息为什么出现在眼前，个人留下了哪些数据，以及如何作出有依据的判断。

## 行业洞见

<!-- item:government-agents -->
### AI 开始替政府执行任务，授权需要具体到每一步

OECD.AI 9 月 25 日刊登政府 Agent 工作组文章，讨论系统从回答问题走向执行动作之后，公共部门如何界定权限、责任与监督。文章提出的判断是：现有治理机制需要延伸到动作层面，不能只检查生成的文字是否正确。

文中以公共服务申请为例，说明 Agent 可以辅助理解要求、收集材料、准备申请及转交办理；涉及敏感动作或正式决定时，则需要明确的同意、授权与责任安排。这些是文章讨论的设计方向，不能读成某个国家已经全面上线的统一制度。

文章也提醒，政府场景中的价值仍待验证。不同部门的数据、法定职责和纠错机制并不相同，适合先从范围清楚的具体任务展开。本文为作者观点，不代表 OECD 或成员国的正式立场。

**编辑观察**：把它与今天的插件和售前案例放在一起看，下一步值得追踪的是任务交接。一个插件能读取资料，并不自然获得替人提交申请的权力；一个原型能演示业务流程，也还没有承担正式系统的责任。

实际评估时，可以沿着一条任务链看：谁发起请求，系统以谁的身份读取资料，哪个动作需要确认，发生错误后谁能停止或撤回。这些问题越早进入设计，团队越容易判断哪些步骤可以交给 AI，哪些步骤仍须保留人工处理。

## 论文速递

<!-- item:qwen-planner -->
### Qwen-Planner-Agent：把手机任务中的失败带回训练

《Qwen-Planner-Agent: A Closed-Loop AI-for-AI Framework for Real-World Mobile Planner Agents》关注长流程手机任务。真实设备上的交互成本高，数据、训练与运行环境之间如果脱节，系统就容易重复犯错。

作者把任务构造、轨迹筛选、训练和部署反馈连接起来，并在人类把关下组织数据循环。运行时得到的动作结果、验证信息和失败记录，可以为下一轮训练与工具配置调整提供材料。

**阅读价值**：它将注意力从单次规划是否漂亮，转向系统如何从执行中积累可用反馈。摘要中的闭环仍包含人工环节，不能概括为完全无人干预的自我进化。本期只核对摘要与提交记录，未核验全文实验及泛化表现。

<!-- item:object-permanence -->
### 训练世界模型记住：物体被遮住，并不等于消失

《Training Object Permanence in World Models》研究视频模型对物体持续存在、实体不能随意穿透等规律的表现。画面看起来流畅，并不必然意味着模型在连续场景中保持了这些约束。

作者构建 WROP，包含六类、150 种可程序化生成的认知任务，并用可控场景改变速度、光照和观察角度；同时提供 300 道测试题，对视频模型进行比较。其训练与评估结果属于作者报告，本期未复现实验。

**阅读价值**：这种设计把“视觉上像真的”和“状态变化一致”拆成可以分别检查的问题。评测仍围绕特定生成任务，不能据此直接判定模型已经理解整个物理世界。

<!-- item:agent-editing -->
### Agent-Editing World Model：先修正错误的任务状态，再决定下一步

Agent 在长任务中可能把未经支持的假设或过期计划带进后续决策。《Agent-Editing World Model: Rethinking World Modeling for LLM Agents》把这类问题视作任务状态受到干扰。

作者提出，先判断动作属于关键、探索或噪声，再修订妨碍后续推理的内部状态，并将这个过程融入执行框架。摘要报告了搜索、终端和软件工程等任务中的改进；本期尚未阅读全文，无法判断不同场景中的收益是否一致。

**需要区分**：这里整理的是 Agent 用于继续决策的内部任务状态，不是授权它改写外部审计记录。系统可以修正自己对任务的理解，同时保留实际发生过什么的独立记录。

## 开源解读

<!-- item:paperclip -->
### Paperclip

**用来做什么**：把不同 Agent 的任务分配、目标、预算和审批放到同一套管理界面。项目使用 Node.js 服务与 React 界面，可连接多种外部 Agent，帮助团队看清一项工作由谁负责、目前走到哪里。

**适合谁**：已经同时使用多个 Agent，希望统一查看任务和成本的个人或小团队。它提供组织与协调功能，但“配置了预算或审批”不自动等于所有执行路径都已受到有效约束；接入后仍需检查实际权限和失败处理。

依据官方 README 与 GitHub API 整理，MIT 许可证；未部署实测。本期作为工具发现，不是当天新发布消息。

<!-- item:model-optimizer -->
### NVIDIA Model Optimizer

**用来做什么**：提供量化、剪枝、蒸馏、稀疏化和推测解码等模型优化能力，并衔接不同的推理运行环境，帮助部署者在模型质量、显存占用与速度之间做取舍。

**适合谁**：已有明确模型、硬件和工作负载的部署团队。比较优化前后的结果时，需要同时看任务质量、总耗时与资源使用，并核对导出格式是否受到目标运行环境支持；工具本身并不保证每种组合都得到相同收益。

依据官方 README 与 GitHub API 整理，Apache-2.0 许可证；未部署实测。本期作为工具发现，不是当天新版本公告。

<!-- item:openbao -->
### OpenBao

**用来做什么**：集中管理密钥、证书和凭证，提供加密存储、访问控制、审计，以及适用后端的动态凭证、租约和撤销能力。

**适合谁**：需要让多个服务或 Agent 调用业务系统，同时希望减少长期凭证散落在脚本与配置中的团队。动态凭证能力取决于具体后端支持；部署工具之后，仍要设计身份、访问策略与凭证有效期。

依据官方 README 与 GitHub API 整理，MPL-2.0 许可证；未部署实测。本期作为基础设施发现，不是当天新发布消息。
