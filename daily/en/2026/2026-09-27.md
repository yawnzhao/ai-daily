## Top Stories

<!-- item:project-swap -->
### Before an agent trades books for you, check whether it understands your preferences

Anthropic’s September 24 Project Swap involved 201 employees trading books through negotiating Claude agents. Participants separately ranked books to assess the agents’ understanding. After short conversations, human and model pairwise preference rankings agreed 61% of the time; **this is not a trade-completion rate**. The study attributes most of the gap from an ideal allocation to preference representation rather than negotiation.

Task execution and goal understanding deserve separate evaluation. This was research among one company’s employees in a controlled market with cooperative models, not evidence of shopping outcomes for all consumers or a commercial trading product already launched.

<!-- item:private-memory -->
### Follow-up: Google explains persistent memory in a protected cloud environment

The September 23 Private AI Compute technical explanation was read in this issue. Devices hold the keys needed to decrypt personal data, which is stored encrypted. For a request, data is temporarily decrypted in an isolated secure cloud environment; added context is encrypted again for storage. Google also proposes public records of server software so devices can verify it before sending data.

The September 24 issue recorded that the body could not be opened; this follow-up supplies the mechanism. The source uses future-facing language, so this reports an architecture and technical plan, not permanent cross-device memory already available to all users. Security was not independently audited, and encryption protection is a separate question from memory accuracy.

## Industry Insights

<!-- item:delegation-check -->
### Our take: a delegated goal also needs a checkable acceptance step

Project Swap suggests a design question: can users see how a system understands a goal before it acts? This is editorial inference, not a deployment design established by the experiment.

For gifts, show two candidates and their trade-offs first. For news, distinguish first publication, follow-up and old material read later. For code, distinguish tested changes from changes ready to release. Example decisions make abstract instructions checkable, while process records help locate deviations.

Evaluate goal understanding, execution outcomes and correction costs together. One successful task does not prove future reliability; more actions do not necessarily better match intent. The ability to revise preferences, correct memory and recover from mistakes is worth tracking.

## Research Briefs

<!-- item:explorationbench -->
### ExplorationBench separates exploration from familiar knowledge

First submitted September 24, the study creates executable, precisely verifiable alien worlds with rules that conflict with familiar knowledge. Systems explore using flawed manuals and environmental feedback, then solve held-out tasks. Two sandboxes each contain 70 tasks, with ten AI systems evaluated.

The abstract reports that stronger systems learn and apply new rules, but exploration trajectories vary considerably and further exploration can stall or regress. Artificial-sandbox results do not establish real scientific-discovery ability. The contribution is measuring experiments, feedback and transfer to new tasks. Only the abstract and submission record were reviewed.

<!-- item:coding-tamp -->
### Coding agents generate planning programs, then face unseen scenarios

The September 24 paper gives coding agents task descriptions and simulators, with a fixed budget to generate programs. Programs are then frozen and evaluated on unseen instances. Across 28 simulated environments, 980 programs each undergo 100 tests, totaling 98,000 evaluation episodes.

For the 16 environments with handcrafted-planner comparisons, the abstract reports average success rates of 56%–95% across three agent configurations, versus 47% for the planner. The range describes different configurations; it does not mean every environment achieved 95%. These simulated task-and-motion-planning results do not establish equivalent real-robot reliability. The full experimental appendix was not reviewed and results were not reproduced.

<!-- item:itersynth -->
### IterSynth separates retrieval planning from evidence synthesis

Submitted September 24, IterSynth divides deep search between a planner, which decides what information is missing, and a synthesizer, which updates a continually evolving evidence summary instead of allowing the search history to grow without limit. Training assigns role-specific learning signals from final outcomes and turn-level scores.

The abstract reports a mean score of 50.7 for an 8B model across five long-search benchmarks. This is an author-reported aggregate score, not general accuracy. Whether the summary drops important counterexamples is a practical risk to assess; that observation is editorial inference. Only the abstract and first-submission time were checked.

## Open Source Spotlight

<!-- item:buzz -->
### block/buzz puts people and agents into a shared event record

Buzz describes a workspace shared by people and agents, using a self-hosted message relay and signed events for messages, workflows and code activity. The README lists channels, search, audit logs, a desktop app and an agent CLI; workflow approval gates are explicitly among features still being wired up.

The useful direction is viewing process and results together. Signatures help establish event identity; they do not prove correctness or complete permission design. README and GitHub API license records were reviewed: Apache-2.0. The tool was not installed or tested. It was discovered on the September 27 ranking, not identified as a same-day first release.

<!-- item:mobile-mcp -->
### mobile-next/mobile-mcp connects agents to mobile applications

The project exposes iOS and Android simulator and real-device operations through MCP. It prefers accessibility structure and falls back to screenshots and coordinates. Official documentation covers taps, swipes, application management and device operations, with platform-specific connection and development requirements.

These are device-interaction tools, not substitutes for understanding intent, authorizing actions or verifying outcomes. Evaluate it as a mobile-app testing tool rather than evidence that agents reliably handle arbitrary phone tasks. GitHub API records show Apache-2.0. Only the repository was read; no device was connected or code executed. It is included as tool discovery.
