企业落地

巴克莱扩大部署 Claude：从代码走向邮件与知识检索

Anthropic 10月1日发布巴克莱扩大合作的公告。银行预计到2026年底，Claude Code 将被约50%的开发者采用，2027年覆盖多数软件工程师。这是采用计划，不是已经完成的覆盖率。

已有应用包括自2025年上线的内部知识助手：公告称超过16,000名同事使用，累计搜索超过100万次；市场业务邮件平台每天分类、补充信息和转发约120,000封邮件。上述数字是合作方报告，本刊核读公告，未独立审计成效。规模化部署同时强调安全、治理和人工监督。本刊观察：衡量企业 AI 的一个实际入口，是它在怎样的流程里被持续使用，而不仅是一次演示是否顺利。

来源：Anthropic · 2026-10-01 · 官方公告全文；数字为合作方报告，未独立审计
工具边界

Claude Code mods：开发者可以改工具，也需要管理信任

Claude 博客10月1日介绍 mods：小型 TypeScript 函数可以介入工具事件，改写提示、调整界面或替换功能；随插件分发，支持 CLI 和桌面端。与既有 hooks 相比，开发者获得更深的执行与交互控制。

Mods 拥有与 Claude Code 相同的本机访问权限，没有沙箱。官方要求只安装可信来源。团队与企业的插件管理继续适用，受管设备默认先加载 sec-default，限制用户 mods 越过既有拒绝规则。它提供定制空间，不能被描述为可放心运行的隔离代码。本刊关联：把检查、审计或团队惯例写进工具，可以减少对用户临时记忆的依赖；但控制能力本身也需要明确边界。

来源：Claude Blog · 2026-10-01 · 官方全文；未部署实测
智力与执行

《永恒互补》：越好的想法，可能越需要执行能力

OpenAI Intelligence Age 平台10月1日刊出 Hemanth Asirvatham、Elliott Mokski 的《The eternal complement》。这是署名作者的经济随笔，代表个人观点，不等于 OpenAI 机构立场或确定预测。

作者将前沿智力与落地能力视为互补品：更好的问题提高仪器的价值，仪器也提高好问题的价值。他们比较两种可能的未来：在有限扩张下依靠更深推理推进，或因自然复杂性而需要更广的实验、制度和后勤。文章引导读者关注把想法实现的工作。本刊观察：巴克莱的流程应用给这一讨论提供了当日案例，但不能用一家银行的部署证明宏观未来已经确定。

来源：OpenAI Intelligence Age · 2026-10-01 · 署名个人随笔全文；不是机构立场或确定预测
算力经济

NVIDIA 谈 AI 工厂回报：能产出，还要有需求和使用寿命

NVIDIA 10月1日的厂商文章将 AI 工厂回报拆成三个因素：满负荷时的产出能力、硬件能持续赚钱的时间，以及实际需求。仅有高吞吐，若卖不出产出，也不足以保证回报。文章强调跨代软件优化与多种工作负载的适配。

本刊核读官方全文；这里采用其分析框架，不把厂商的性能优势、硬件寿命或收益预测当作独立实测结果。与本期经济随笔放在一起，值得继续追问的是：提高能力之后，谁提供真实需求，谁负担部署与融资，谁承担利用率不足的成本？

来源：NVIDIA Blog · 2026-10-01 · 厂商全文；性能和收益未独立实测

Olmo-core 3：开放 MoE 训练系统，万亿参数是系统测试口径Apache-2.0

Ai2 10月1日发布 Olmo-core 3 介绍，改进大型混合专家模型的训练基础设施。MoE 每个 token 只激活部分专家，但完整模型仍占用显存，跨卡路由也要付出通信成本。新栈让专家留驻 GPU，再将数据送往专家，避免旧实现反复汇集权重。

作者报告的一项测试将专家数从8增至128，每个 token 仍选4个专家、活跃参数约32亿，总参数由46亿升至470亿，吞吐下降不足5%。此外，1.2万亿参数、512张 B300 的测试使用随机路由衡量系统性能；2.38万亿参数是短时容量测试。不能据此声称一个对应规模、已完成训练的新模型发布了。

已核官方博文、仓库 README 和 Apache-2.0 许可证，未部署。README 提醒镜像和依赖受硬件、驱动与 CUDA 版本影响。本刊观察：开源的不只是权重，训练系统及其性能口径也值得审阅；实际吞吐取决于完整系统，不能把某个内核变快直接当作端到端变快。
